# 2.18.0: Installs on current ComfyUI-Manager, typed dynamic groups
2026-11-17

## Manager

### Installs work on current ComfyUI-Manager
<!-- weight: major -->
`manager.installModel` and `manager.installPlugin` go through the Manager's install queue on every Manager generation: the legacy custom node (V3.x) and the pip Manager 4.x, with its default UI or its legacy UI. Before, they called routes that Managers no longer serve and always resolved `false`. Both now resolve only when the Manager ran the install and the result is checked, so a large model can take minutes. `timing.installTimeoutMs` (default 1 hour) bounds the wait. A refused install logs the route and what the host said, and a refusal by the Manager 4.x security policy names the settings it wants.

### Plugin and model status on every Manager
<!-- weight: feature -->
`fetchPlugins`, `fetchModels`, `isPluginInstalled`, `getPluginStatus`, `isModelInstalled` and `getModelStatus` work again on Manager V3.x, whose list changed shape, and now on the Manager 4.x default UI, which serves no list: there the view is built from what the host has installed and the bundled registry. A pack or a model the host cannot decide has the status `unknown` in `getPluginStatus` and `getModelStatus`, and the yes or no checks `isPluginInstalled` and `isModelInstalled` answer `false` for it. On the 4.x default UI `update-available` is never reported.

### `manager.api()` says which Manager the host runs
<!-- weight: feature -->
It returns `{ generation: 'v3' | 'v4-legacy-ui' | 'v4', version }`.

### `manager.configureLogging` throws when the host does not serve its route
<!-- weight: improvement -->
A change of behavior: no current Manager serves it. Before, it returned the error page as text.

## Types

### Dynamic group inputs are typed
<!-- weight: feature -->
ComfyUI 0.45 adds `COMFY_DYNAMICGROUP_V3` inputs, used by `LoadLoraModel.loras` and `LoadLoraTextEncoder.loras`. The generated sdk types them as a list of rows with at least one row, `b.LoadLoraModel({ model, loras: [{ lora_name, strength }] })`, and a workflow that uses them imports and exports the way the editor saves it. Before, these nodes could not be built from typed code.

## Runs

### An interrupted run settles
<!-- weight: improvement -->
`execution.done` now resolves as a failure when the server interrupts the run. Before, it never resolved.

### No noise for events a server sends by design
<!-- weight: improvement -->
Asset seeding, agent status and Manager queue events are ignored by name. A type that is really unknown prints one error per type per connection, not one per frame.

### A host whose node sends a three part input spec connects without a schema error
<!-- weight: improvement -->

## Workflows

### `toWorkflowJson` exports dynamic combos and widgets fed by a link
<!-- weight: improvement -->
They are exported as the editor saves them. Before, a dynamic combo became an empty slot, and a widget fed by a link lost its value, which shifted every widget after it on the next import.

### Official templates import more exactly
<!-- weight: improvement -->
A seed inside a dynamic combo no longer shifts the widgets after it (every `TextGenerate` node was affected). Widget inputs of custom types such as `BOUNDING_BOXES` and `COLORS` keep their value. A subgraph widget that feeds a slot input reaches the prompt. A workflow file with a text `last_node_id` or empty slot fields loads. When every output of a converted workflow misses a required input the import throws, and when only some do it warns and names the outputs ComfyUI will skip.
